# Global Desk / Tops — 가설 검증 시스템

지방 제조·수출 기업 대상 **크로스보더 운영·무역 리스크** 서비스의 가설을
인터뷰/설문 전에 검증하기 위한 경량 웹앱.

- **[Public] 고객 설문** — 리얼보이스 문항 + 인력/팀 구조 수집 + 바이럴 공유 장치
- **[Private] 창업자 대시보드** — 30개 가설(T1~T30)을 실시간 룰 매칭 → 누적 데이터로
  `Validated / Pivot / Fail` 동적 판정 + 세일즈 파이프라인

## 파일 구조
| 파일 | 역할 |
|---|---|
| `hypotheses.py` | 애트리뷰트 사전, **가설 매트릭스 T1~T30**, 룰 기반 매칭, 동적 판정 알고리즘 |
| `db.py` | SQLite 스키마(고객사+인력구조+매칭+바이럴 통합) 및 저장/조회 |
| `content.py` | 화면 카피 + 카톡/이메일 **공유 메시지 템플릿** |
| `app.py` | Streamlit 라우팅(공개 설문 ↔ 창업자 대시보드) |

## 실행
```bash
pip install -r requirements.txt
streamlit run app.py
```
- 고객 설문:  `http://localhost:8501`
- 창업자 대시보드:  `http://localhost:8501/?admin=1`  (비밀번호 **admin1234**)
- 바이럴 유입 추적:  `.../?ref=<코드>` → `referred_by`에 저장

## 배포 전 반드시 바꿀 것
1. `app.py` 의 `ADMIN_PASSWORD` — 실제 비밀번호로 교체 (또는 `st.secrets` 사용)
2. `app.py` 의 `BASE_URL` — 실제 배포 도메인 (공유 링크 생성에 사용)

## 가설 판정 규칙 (튜닝 지점: `hypotheses.py` 상단 임계치)
- **VALIDATED** — 표본 충분 + 실제 비중 ≥ 기대×0.5 + 실제 미팅률 ≥ 기대×0.8
- **PIVOT** — 표본은 왔으나 미팅률이 기대 미달 → 메시지/오퍼 수정
- **FAIL** — 기대는 높았는데 표본이 거의 없음 → 페르소나 재검토
- **INSUFFICIENT** — 표본 < 3건 (판정 보류)
- 검증점수 = 비중달성률×0.4 + 미팅달성률×0.6 (0~100)
